## Processing decisions

- dft_results.csv: 37 rows = 27 candidate runs + 10 spin-state sensitivity runs (names '<candidate>__afm*', label_reasons 'spin-state sensitivity run'). Sensitivity runs are attached to their parent candidate as diagnostics and never counted as labels.
- Primary key: exact candidate `name`; `slug` is a URL/file-safe copy (identical to `name` for this snapshot).
- Join: QC-passed catalogue (passed.csv) LEFT JOIN zeopp.csv, iteration predictions and DFT results on `name`.
- DFT status: label_ok=True -> accepted; label_ok=False -> rejected (shown as 'Not accepted / diagnostic'); no row -> not_available; several candidate runs or missing label_ok -> ambiguous.
- Accepted DFT gaps are exported in `dft.gap_eV`. For non-accepted runs any gap is exported only as `dft.diagnostic_gap_eV` and never displayed as a validated value.
- Displayed geometry is the PORMAKE-generated CIF for every candidate. For accepted labels, the DFT-relaxed geometry (static-run POSCAR chosen with the label_folder() rule of scripts/22_structure_figures.py) is exported separately and labelled 'DFT-relaxed'.
- Missing/NaN/inf values -> null. Booleans normalised from True/False strings.
- xTB results are NOT exported (different method; kept out of all PBE columns).
